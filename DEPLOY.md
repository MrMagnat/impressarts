# Деплой на сервер клиента + удалённый «выключатель»

Приложение упаковано в один Docker-образ (backend API + собранный фронтенд + Chromium для PDF).
Встроена **лицензия-выключатель**: клиент не сможет работать, если вы отзовёте лицензию.

---

## 1. Как работает выключатель (важно)

- Приложение раз в `LICENSE_POLL_MIN` минут запрашивает подписанную лицензию по адресу
  `LICENSE_URL`, **который контролируете вы** (ваш VPS, GitHub Gist, S3 — любой статический URL).
- Лицензия подписана вашим приватным ключом (Ed25519). Клиент **не может её подделать** —
  приватный ключ есть только у вас (`ops/license/vendor-private.pem`).
- Приложение **блокируется** (все экраны → «Доступ приостановлен», API → 503), если:
  - в лицензии `"active": false`, **или**
  - истёк срок `exp`, **или**
  - `LICENSE_URL` недоступен дольше `LICENSE_GRACE_HOURS` (по умолчанию 72 ч) — то есть клиент
    не сможет «оживить» приложение, просто заблокировав ваш URL (**fail-closed**).

**Чтобы отключить клиента:**
```bash
cd ops/license
node sign-license.mjs --customer "ООО Клиент" --days 60 --inactive --id impress-sklad-001 > license.json
# загрузите новый license.json на ваш LICENSE_URL (перезапись файла)
```
Через ≤ `LICENSE_POLL_MIN` минут приложение у клиента заблокируется. Чтобы снова включить —
выпустите лицензию без `--inactive` и обновите файл.

> Честно о границах: приложение стоит на сервере клиента, у клиента есть root. Технически
> подготовленный клиент может пропатчить код и обойти проверку. Против такого помогает только
> SaaS (держать приложение у себя). Для обычного клиента этой защиты достаточно, а fail-closed
> не даёт «просто отрубить интернет».

## 2. Подготовка (один раз, у вас)

1. Ключи уже сгенерированы: `ops/license/vendor-private.pem` (**секрет, храните у себя, не на сервере клиента**).
   Публичный ключ вшит в приложение.
2. Выпустите стартовую лицензию и разместите её по вашему `LICENSE_URL`:
   ```bash
   cd ops/license
   node sign-license.mjs --customer "ООО Клиент" --days 60 --id impress-sklad-001 > license.json
   # положите license.json на ваш URL (например, приватный gist → raw-ссылка)
   ```
3. Заполните `.env` (скопируйте из `.env.example`):
   - `AUTH_PASSWORD` — сильный пароль входа;
   - `COOKIE_SECRET` — случайная строка (`openssl rand -hex 32`);
   - `LICENSE_URL` — ваш адрес лицензии.

## 3. Деплой на сервер

**Рекомендуется сперва настроить вход по SSH-ключу** (безопаснее пароля):
```bash
ssh-copy-id op@192.168.233.2
```

Затем одной командой:
```bash
SSH_HOST=op@192.168.233.2 ./ops/deploy.sh
```
Скрипт скопирует проект в `/opt/impress-sklad` и выполнит `docker compose up -d --build`.

> На сервере нужны `docker` и `docker compose`. Если их нет:
> `curl -fsSL https://get.docker.com | sh`

## 4. Доступ к приложению

По умолчанию контейнер слушает **только `127.0.0.1:8080`** на сервере (наружу не торчит).
Варианты открыть:

- **SSH-туннель** (безопасно, ничего не открываем наружу):
  ```bash
  ssh -L 8080:127.0.0.1:8080 op@192.168.233.2
  # затем http://localhost:8080
  ```
- **В локальной сети клиента**: в `docker-compose.yml` поменяйте порт на `"8080:3000"`
  и откройте `http://IP-сервера:8080`.
- **Публично + HTTPS**: поставьте nginx/Caddy с TLS перед контейнером (по запросу дам конфиг).

Вход: логин по паролю `AUTH_PASSWORD`.

## 5. Обновление данных из 1С

- Вручную/по расписанию: положите свежую Excel-выгрузку и импортируйте через раздел
  **Настройки → Импорт**, либо на сервере:
  ```bash
  docker compose exec sklad npx tsx src/etl/seed.ts /path/to/new.xlsx
  ```
- Для «каждый день» — cron на сервере, кладущий выгрузку и вызывающий импорт.

## 6. Управление контейнером

```bash
docker compose logs -f          # логи (видно статус лицензии при старте)
docker compose restart          # перезапуск
docker compose down             # остановить
docker compose up -d --build    # обновить после изменений
```

## 7. Безопасность — чек-лист

- [ ] Смените SSH-пароль, который вы присылали, и перейдите на SSH-ключи.
- [ ] Сильный `AUTH_PASSWORD` и случайный `COOKIE_SECRET` в `.env`.
- [ ] Наружу не открывать без TLS; для одного пользователя — SSH-туннель.
- [ ] `ops/license/vendor-private.pem` — только у вас, НИКОГДА на сервере клиента.
- [ ] Файрвол сервера: закрыть всё лишнее.
