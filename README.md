# Складской дашборд (управление запасами · данные из 1С)

Веб-панель управления складскими запасами: **Дашборд · Каталог · Отчёты · Настройки**.
Стек: TypeScript — Fastify + `node:sqlite` (backend/API), React + Vite + Tailwind + Recharts (frontend).

## Что внутри
- **Каталог** — дерево `Тип → Вид номенклатуры → Позиция → Партии`, drill-down, поиск, «заморожено в деньгах» на каждом уровне. Карточка позиции: партии (серия, изготовлено, годен до, остаток дней, менеджер, заказчик), менеджеры/заказчики, история за 78 недель, конкурентный отчёт. В таблице партий ширину колонок можно тянуть мышью, настройка сохраняется в браузере.
- **Дашборд** — KPI (заморожено ₽, тоннаж, позиции, партии), динамика запасов **с накоплением по типам**, структура по типам, топ категорий, сроки годности, топ менеджеров/заказчиков. Переключатель ₽/кг и фильтр по типу номенклатуры для сроков годности, менеджеров и заказчиков.
- **Сроки годности** — отдельный отчёт: сводка по корзинам (просрочено / ≤30 / 31–60 / 61–90 / >90 / без срока) и детализация по номенклатуре с раскрытием до партий, фильтры по типу и сроку, сортировка по любой колонке, экспорт в PDF. Фильтр по корзине применяется и к раскрытию: выбрав «Просрочено», внутри позиции видно только просроченные серии.
- **Отчёты** — недельные и месячные, сравнение с предыдущим и средним периодом, раскрытие по **виду номенклатуры** (поле `Parents`), топ-движения, экспорт в **PDF**.
- **Настройки** — источник данных 1С, цены ₽/кг по видам (пересчёт сумм), импорт Excel-выгрузки, глубина хранения, журнал ошибок приложения, общие параметры и пароль.

### Шаг сравнения
«Прошлый период» на дашборде и в недельных отчётах отсчитывается не от соседнего снимка, а на
**28 дней назад** (меняется в Настройки → Общие). Снимки из 1С приходят ежедневно, и за сутки
остатки почти не меняются — сравнение с вчера показывало шум вместо динамики. Среднее тоже
считается по точкам, отстоящим на кратные шаги, а не по восьми подряд идущим дням.

## Источник данных 1С
Приложение раз в сутки обращается к HTTP-сервису 1С и забирает остатки на текущую дату:
```
http://192.168.0.49/erp-work/hs/1c_II?date=01.09.2026
```
Адрес меняется в **Настройки → Источник 1С** (плейсхолдер `{date}` подставляется как `ДД.ММ.ГГГГ`).
Формат ответа распознаётся автоматически: JSON, CSV/TSV или вложенный `.xlsx`; колонки
сопоставляются по именам, а не по порядку, кодировка UTF-8 или windows-1251.

Реальные поля сервиса и их роль в дашборде:

| Поле 1С | Что это |
|---|---|
| `Name` | номенклатура; текст до первого двоеточия становится группой |
| `TypeN_Name` | тип номенклатуры — верхний уровень дерева (из двух колонок берётся именно `_Name`: `TypeN` рядом отдаёт код) |
| `Parents` | родитель в дереве 1С, ложится в «вид» — второй уровень дерева и разрез отчётов (к нему же привязана цена ₽/кг) |
| `Series` | серия/партия |
| `BalanceKG` | остаток, кг |
| `CostRub` | **реальная стоимость остатка, ₽** |
| `MFD`, `ExpD` | изготовлено и годен до — основа отчёта по срокам |
| `Manager`, `Client` | менеджер и заказчик |
| `Date` | дата снимка |

`MapRoad` приходит, но не используется — он дублирует связку тип/родитель. Поле `grp` (текст
до первого двоеточия в названии) осталось в модели данных, но из навигации и отчётов убрано:
в реальной выгрузке двоеточия нет у большинства позиций, и уровень вырождался в «Без группы».

**Деньги считаются по `CostRub`, а не по модельным ценам.** Таблица цен ₽/кг в Настройках
остаётся запасным механизмом для строк без стоимости; ₽/кг в карточке позиции выводится
обратным счётом как `CostRub / BalanceKG`. Если сохранить цены вручную при загруженных из 1С
данных, суммы по этому виду будут пересчитаны как «остаток × цена» и заменят факт — в
интерфейсе об этом предупреждает отдельная плашка.

Что делает ежедневный прогон:
- находит **новые позиции** — их нет в каталоге, они заводятся;
- по существующим позициям фиксирует **приход и списание** — записывается снимок на дату;
- сверяет итоги с базой и пишет расхождения в журнал.

Режим «Только сверять» ничего не пишет в базу — полезен, пока проверяется разбор формата.
Каждое обращение видно в журнале на вкладке «Источник 1С» и в логах сервера с префиксом
`[sync]` (`docker logs impress-sklad`). Кнопка **«Показать сырой ответ»** отдаёт начало тела
ответа и разбор колонок — по ней настраивается сопоставление, если 1С отдаёт непривычные имена.

## Производительность

Реальная выгрузка — около 40 тысяч строк и 20 МБ на дату, в тринадцать раз больше
демонстрационной. Чтобы дашборд не проседал под таким объёмом, сделано следующее.

- **Кэш ответов в памяти** — дашборд, каталог и отчёты считаются один раз и отдаются
  из памяти, пока данные не изменились. Любая запись в базу поднимает версию данных
  и разом обнуляет кэш, так что устаревших цифр не бывает.
- **Каталог читает агрегат.** Уровни «тип» и «группа» берутся из `fact_agg`, а не
  джойном детальных таблиц; детализация нужна только на уровне позиций.
- **Индексы по дате** в таблице партий: без них каждый расчёт сроков годности и топа
  менеджеров перебирал всю таблицу.
- **Сжатие истории — фоновое и порционное.** Старые снимки сжимаются по одной дате
  за такт событийного цикла, поэтому импорт не ждёт уборку, а интерфейс не замирает.

Замеры на 40 тысячах строк, до и после:

| Операция | Было | Стало |
|---|---|---|
| Импорт снимка | 15,1 с | 6,1 с |
| Дашборд, первый заход | 455 мс | 155 мс |
| Дашборд, повторный | 455 мс | 3 мс |
| Каталог | 485 мс | 2 мс |
| Отчёт по срокам | 242 мс | 5 мс |

## Хранение истории
Многолетняя история **не** держится в дашборде целиком — она живёт в 1С и подтягивается по требованию.

| Слой | Что хранит | Глубина |
|---|---|---|
| `fact` + `batch` | остатки по позициям и партии: карточка, поиск, менеджеры, топ-движения | горячее окно, по умолчанию 120 дней |
| `fact_agg` | суммы по дереву тип → вид → группа | вся известная история, ~120 строк на дату |

После каждой загрузки всё, что старше окна, сжимается в агрегат: дашборд, тренды и отчёты по
категориям продолжают показывать полную глубину, а объём базы перестаёт расти линейно по позициям.
Недостающие точки прошлого догружаются из 1С кнопкой **Настройки → Хранение → Догрузить историю**
(шаг «месяц» — примерно 12 запросов на год) и сохраняются сразу агрегатом.

Что недоступно за пределами горячего окна: топ-движения по позициям и разрез по
менеджерам/заказчикам — они требуют детализации. Отчёт за такой период просто показывает эти
блоки пустыми.

Данные: реальная выгрузка `data/seed/demo.xlsx` (снимок на 14.08.2026, 41 838 партий, 3 036 позиций). История по неделям **смоделирована** назад на основе трендов/сезонности. Цены **модельные** (₽/кг по видам) — заменяются на прайс из 1С позже.

**Смоделированная история удаляется при первом импорте реальной выгрузки** (и кнопкой
Настройки → Хранение → «Удалить смоделированную историю»): рядом с фактом модельные точки
искажают тренды и сравнения. Реальные снимки при этом не трогаются.

## Запуск (локально)
```bash
npm install
npm --workspace server install
npm --workspace web install
npm run etl          # собрать БД из data/seed/demo.xlsx + смоделировать историю
npm run build        # собрать фронтенд
npm start            # сервер на http://localhost:3000 (отдаёт и API, и UI)
```
Режим разработки (два порта, hot-reload):
```bash
npm run dev          # server :3021 + web :5199
```

**Пароль по умолчанию:** `demo` (меняется в Настройках или через `AUTH_PASSWORD`).

## Переменные окружения
- `PORT` (по умолчанию 3000), `HOST` (0.0.0.0)
- `AUTH_PASSWORD` — пароль входа
- `COOKIE_SECRET` — секрет подписи cookie (задать в проде)
- `DB_PATH` — путь к файлу БД (по умолчанию `data/sklad.db`)
- `SOURCE_URL` — стартовый адрес HTTP-сервиса 1С (дальше меняется в Настройках)
- `SOURCE_LOGIN`, `SOURCE_PASSWORD` — если сервис за Basic-авторизацией

## Журнал ошибок
Ошибки отчётов, экспорта в PDF и импорта файлов пишутся в базу и видны в интерфейсе:
**Настройки → Журнал ошибок** (последние 500 записей, с раскрытием до стектрейса). Те же события
идут в логи сервера — `docker compose logs -f`. Обращения к 1С остались на своей вкладке
«Источник 1С».

## Обновление данных
Штатно — автоматически, раз в сутки из HTTP-сервиса 1С (см. выше). Запасные пути: **Настройки →
Импорт файлом** или `npm run etl <путь к .xlsx>`.
